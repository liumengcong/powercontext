# 项目说明与演示讲稿

以下内容按**最终实际实现**编写，未加入尚未做到的功能。可直接复制到报名表单。

## 1. 一句话介绍

研习台（StudyFlow）：让下一次学习，从上次的进展继续——本地单用户工具，用 PowerContext 开源组件
把笔记、薄弱点、待办与偏好存成可溯源的记忆，重启后读回并生成带出处的继续学习清单与复盘初稿。

## 2. 项目简介（约 200 字，可直接粘贴）

> 学生和科研人员的笔记、薄弱点、待办常散在多个聊天会话和文档里：换个窗口就得重讲一遍背景，
> 上周卡在哪也没人记得。研习台把这些内容写进 PowerContext 的记忆层（`atomic_memory`），
> 每条都保留原文、`art_…` artifact ID 与 revision，界面上任何一条建议都能点「查看出处」
> 回到原文。关掉进程再打开，它从 PowerContext 重新读取上次的进度与学习偏好：写「一次学 25 分钟」，
> 下一步就只排 2 个任务，并说明这条建议来自哪条偏好、用了哪条规则。检索走 PowerContext 的全文检索，
> 中文行为已实测；查不到就明确说查不到，不编结果。待办状态以追加式事件保存，两个窗口同时改同一条
> 会返回版本冲突而不是悄悄覆盖。复盘导出为 UTF-8 Markdown，逐条带引用并提示需本人核对。
> 全部数据留在本机 `127.0.0.1`，规则整理不调用生成式模型。

## 3. 痛点 ↔ 实现对照

| 痛点 | 研习台的做法 | 可核验位置 |
| --- | --- | --- |
| 上下文换会话就丢 | 记忆与状态存 PowerContext scope，不在浏览器本地 | 「继续学习」页重启后仍能读回；`tests/test_powercontext_real.py` |
| AI 摘要不敢信、查不到原文 | 每条建议附 `art_…` + revision + 原文，点开即出处弹窗 | 「记忆库」「继续学习」的「查看出处」 |
| 推荐不区分时长 | 从记忆读回学习偏好，规则决定任务数量并写明规则 | 25 分钟 ⇒ 最多 2 项，界面显示规则说明 |
| 检索结果像黑箱 | 调用真实 PowerContext 查询，空结果直说空 | 「检索」页；演练检查 2b/2c |
| 多窗口互相覆盖 | 状态为追加式事件 + 期望序号，冲突返回 409 | 「待办」页；演练检查 4b/4b2 |
| 复盘要手写、也容易被编 | 规则整理生成 Markdown 初稿，逐条带引用、标注需核对 | 「复盘导出」下载 `.md` |

## 4. 技术路线（照实说）

- 前端：无构建步骤的原生 HTML/CSS/JS（`frontend/`），左侧导航 + 右侧宽内容区。
- 后端：Python 3.12 + FastAPI + uvicorn（**单进程**，绑定 `127.0.0.1:8712`）。
- 记忆层：`powercontext[builtin]==1.5.1` 内置 runtime，**在应用进程内**通过官方 Python API 使用，
  持久化为本地 SQLite（`sqlite+aiosqlite:///qoder/data/powercontext.db`）。
  未接入独立 seekdb，也不做该声称。
- 工作区 → PowerContext scope 一一映射；scope 是数据选取边界，不是身份认证。
- 检索：SQLite FTS5 + BM25 全文检索（含中文分词资源），未配置 embedding 模型，实测 `embedding_calls=0`。
- 生成：全部为确定性规则整理，不调用任何生成式模型。

## 5. 明确边界（答辩时先说，避免被当成夸大）

- 本地单用户工具：无账号体系、无并发多用户保证；写冲突保护只在**单进程**内有效。
- 记忆正文修订：1.5.1 未提供公开的正文修订入口，因此不显示「已更新原记忆」，而是追加状态事件。
- 「已遗忘」的记忆不参与任何推导，但在记忆库筛选 `states=all` 时仍可见。
- 展示站是静态页面，只展示截图与说明；**交互必须在本机运行 Python 后端**，不假装在线服务。
- 没有真实用户试用数据：不含用户数、提效百分比、真实反馈。

## 6. 演示讲稿（约 5 分钟）

准备（演示前一次即可）：

```bash
cd qoder
../../work/pc-env/bin/pip install -r requirements.txt   # 或直接用已准备好的环境
../../work/pc-env/bin/python -m backend.app             # http://127.0.0.1:8712/
```

| 时间 | 操作 | 讲解要点 |
| --- | --- | --- |
| 0:00–0:30 | 打开 `http://127.0.0.1:8712/`，指右上角状态徽标 | 「研习台，让下一次学习从上次的进展继续。右上角是**真实**连接状态：绿色才代表连上了 PowerContext，显示的是包版本、runtime 模式与数据库路径，不是我写死的文案。」 |
| 0:30–1:10 | 点「导入演示数据」→「记忆库」 | 「这条『一次学 25 分钟』的学习偏好，和这些笔记、薄弱点，都不是存在浏览器里，而是 PowerContext 的 `atomic_memory`。每张卡片显示真实 artifact ID、revision，「查看出处」就是写进去的原文。」 |
| 1:10–1:50 | 「检索」输入「幻读」 | 「查询直接调 PowerContext。中文行为我实测过：命中这条笔记和这个薄弱点。注意它显示的是全文检索，`embedding_calls=0`——我没配 embedding 模型，所以不会假装是语义检索。换个不存在的词，它回『未返回匹配记忆，应用不会编造结果』。」 |
| 1:50–2:40 | **`Ctrl+C` 停掉后端并重启**，刷新「继续学习」 | 「关键在这里：进程重启，页面重新从 scope 读。已完成、当前阻塞、下一步都回来了；因为记忆里写着 25 分钟，下一步只排 2 项，规则那一行写明白了依据哪条偏好——出处 `art_…`。」 |
| 2:40–3:30 | 「待办」把一项标记完成；再开一个隐身窗口对同一条点「重做」 | 「状态更新是**追加一条 `task_status` 事件**，带期望序号。第二个窗口拿着旧序号，返回 409 版本冲突并提示刷新——不会静默覆盖别人。」（现场开两个窗口不便时，说明并发回归测试与 `server-2.log` 中的 `200 OK`/`409 Conflict` 交错行。） |
| 3:30–4:10 | 「复盘导出」下载 `.md` | 「导出的初稿逐条带引用，只写有记录的事，顶部标注需本人核对。文件是 UTF-8，`Content-Type: text/markdown; charset=utf-8`。」 |
| 4:10–4:40 | 「验证记录」页 | 「这一页是应用对 PowerContext 的真实操作流水：写入、读回、查询、状态更新与冲突，每条带成功/失败和返回条数。只有操作类型和结果，不记密码与令牌。」 |
| 4:40–5:00 | 打开 `qoder/docs/evidence/20261116-112831/evidence.json` | 「这些不是我口述：脚本真实启停服务 3 次，12 项检查 0 失败，含上面每一步的实测值和真实 scope/artifact ID。测试 20 项通过，其中 5 项跑真实 PowerContext runtime。」 |

收尾一句：「核心价值是一个——记忆不靠聊天窗口的上下文，靠 PowerContext 存下来、读回来，
而且每一步都能查到出处。」

可选加演（真的把 runtime 关掉，看界面会不会假装正常）。后端需以
`STUDYFLOW_ALLOW_DESTRUCTIVE_DEV=1` 启动，该开关默认关闭：

```bash
curl -X POST http://127.0.0.1:8712/api/dev/disconnect   # 真实关闭 PowerContext runtime
curl -s -o /dev/null -w "%{http_code}\n" http://127.0.0.1:8712/api/health   # 期望 503
curl -X POST http://127.0.0.1:8712/api/dev/reconnect
```

此时刷新页面：状态徽标变红、各面板显示「读不到」而**不**回显上一次的数据，
写操作直接被拒。恢复用 `dev/reconnect`。
