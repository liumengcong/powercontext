# 可复现验收样例

以下为预期行为，不是测试通过报告。Qoder 实现后，需将实际命令、输出和截图写入 `验证结果.md`。

## 1. 干净环境启动

按最终 README 安装锁定依赖。启动应用，查看真实 PowerContext 状态。断开组件时界面必须说明无法读写，不能继续显示成功。

## 2. 导入、检索与引用

导入 `sample-data.json`，记录实际导入数量、scope、artifact ID/revision。再次导入，记忆总数应保持不变。检索“幻读”，结果应包含演示课程笔记与薄弱点，展示真实原文和实际 PowerContext 引用。检索一个不存在的词，应显示无结果，不生成虚构答案。

## 3. 真正跨会话继续

记录导入结果后，停止后端进程、关闭页面，再重新启动并打开新页面。不要清除数据目录。继续学习页应从 PowerContext 读回 25 分钟偏好、当前进度与薄弱点，建议任务不超过两项，并明确引用它们来自哪些记忆。通过读回日志核对引用确实存在。

## 4. 状态更新与持久化

将“整理事务隔离级别对照表”标为完成，再重启。它仍应显示完成，未完成的另一项保持待办。保留变更前后 artifact revision 或所用真实状态变更证据。以旧版本重复更新，应用应给出冲突提示，不能静默覆盖。

## 5. 工作区隔离

切换到全新的工作区，不能看到演示工作区内容。创建一条记忆后切回演示工作区，也不能混入新工作区的记忆。scope 仅用作本地数据边界，不代表多用户认证。

## 6. 导出复盘

导出 UTF-8 Markdown，内容包含已完成事项、未完成事项、下一步和精确记忆引用。没有记录的使用时长、论文数量、提效比例不能被生成。导出的中文应正常显示。

## 7. 展示与发布

网站必须包含真实项目截图、源码入口与运行方式。用 Qoder Sites 发布后，在未登录窗口打开完整网址，确认公开可见、图片能加载、源码链接有效。若网站只提供展示入口，应写清本地运行步骤。

## 证据要求

保留：环境版本、安装与启动命令、上述操作结果、重启前后读回日志、PowerContext 实际作用、真实 Qoder 对话截图、UID 和 Sites 公开访问截图。

日志与截图先检查是否含凭据；需要展示用户反馈时隐去个人信息。
