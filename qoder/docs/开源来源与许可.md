# 开源来源与许可

本项目（研习台 / StudyFlow）在 `oceanbase/powercontext` 仓库的 `2026-competition-ecosystem` 分支上开发，
核心记忆能力由开源组件 PowerContext 提供。下列信息取自本机虚拟环境里**实际安装的包元数据**
（`work/pc-env/lib/python3.12/site-packages/*/dist-info`），不是凭印象写的。

## 1. 本项目自己的许可

- 目录：`qoder/`（`backend/`、`frontend/`、`tests/`、`scripts/`、`site/`、文档）
- 许可：Apache License 2.0，全文见 `qoder/LICENSE`
- 上游依赖同为 Apache-2.0，二者兼容

## 2. 直接依赖

| 包 | 本机实装版本 | 许可 | 用途 | 来源 |
| --- | --- | --- | --- | --- |
| `powercontext[builtin]` | 1.5.1 | Apache-2.0（包内 `dist-info/licenses/LICENSE` 为 Apache 2.0 全文） | 记忆写入、读回、检索、状态、遗忘、scope 隔离、审计事实 | https://github.com/oceanbase/powercontext |
| `fastapi` | 0.163.1 | MIT | HTTP 接口 | PyPI |
| `uvicorn` | 0.54.0 | BSD-3 | ASGI 服务器（单进程） | PyPI |
| `pydantic` | 2.14.3 | MIT | 请求/响应模型与入参校验 | PyPI |
| `httpx` | 0.28.1 | BSD-3 | 测试用 ASGI 传输 | PyPI |
| Python 标准库 `sqlite3`/`json`/`asyncio` | 3.12.14 | PSF | 运行基础 | — |

`powercontext[builtin]` 自身带入的传递依赖共 70 余个，本机实装版本全部冻结在
`qoder/requirements.lock.txt`（`pip freeze` 生成，79 行）。其中与本项目行为相关的：

| 传递依赖 | 版本 | 许可 | 与本协议的关系 |
| --- | --- | --- | --- |
| `sqlalchemy` | 2.1.8 | MIT | PowerContext 用 `sqlite+aiosqlite://` 连接本地 SQLite |
| `aiosqlite` | 0.22.1 | MIT | 异步 SQLite 驱动 |
| `jieba` | 0.42.1 | MIT | PowerContext 内置中文分词资源 |
| `sqlite-vec` | 0.1.9 | MIT/Apache-2.0（上游声明） | 随 `[builtin]` 安装；本项目未配置 embedding 模型，实测 `embedding_calls=0`，**该向量扩展未参与本项目的检索路径** |
| `alembic` / `apscheduler` / `pycasbin` / `cryptography` / `filelock` / `pydantic-ai-slim` 等 | 见 lock | 各自上游许可 | 由 PowerContext runtime 使用，本项目代码不直接调用 |

PowerContext 包内另附 `LICENSES/stopwords.txt`，说明其自带的中英文停用词表来自
`stopwords-iso`（MIT）。这些内容随 `powercontext` 包一起分发，本项目不复制、不重分发。

## 3. 我们如何使用上游组件（不做超出事实的声称）

- 只使用已公开安装的 1.5.1 API：`open_builtin_runtime`、`BuiltinConfig`/`SQLiteConfig`/`RuntimeConfig`、
  `ScopeDraft`、`runtime.scopes.*`、`runtime.atomic_memory.for_scope(...).{create,list,get,search,forget,manifest}`、
  `runtime.capabilities()`。调用点行号见 `qoder/README.md` 第 2 节表格。
- **未使用** seekdb / 独立服务 / 分布式部署：本机以 `sqlite+aiosqlite:///…` 文件数据库跑内置 runtime，
  因此文档只写「PowerContext 开源自托管运行时」，不写「OceanBase seekdb 生产部署」。
- 检索实测为 SQLite FTS5 + BM25 全文检索（`matched_by=["text"]`、`embedding_calls=0`），
  界面文案写「全文检索」，不写「语义检索」。
- 未使用任何生成式模型：继续学习建议与复盘初稿是确定性规则整理，界面与导出文件里都标注
  「规则整理，未调用生成式模型」。
- 1.5.1 未提供公开的记忆正文修订入口，因此待办状态用**追加式** `task_status` 事件记忆表达，
  产品界面显示的是「事件序号 seq」，不谎称「内容 revision 已更新」。
- 官方文档地址（供核对）：https://powercontext.oceanbase.io/en/docs/ 。本项目依据的是
  1.5.1 实际安装包的接口与行为，未按 1.5.2 文档编写。

## 4. 数据与内容来源

| 内容 | 来源 |
| --- | --- |
| `qoder/sample-data.json` 及界面中全部演示记忆、待办、笔记 | 本项目**手工编写的合成数据**，参照公开技术常识撰写，不对应任何真实用户、真实课程或真实反馈 |
| `qoder/docs/evidence/**` | 本仓库脚本 `scripts/acceptance_drill.py` 在本机真实运行产生的日志与 `evidence.json`（含真实的 `art_…`/`scp_…` 技术标识） |
| `qoder/site/dist/screenshots/**` | 本机 Chrome 无头模式对运行中的 `http://127.0.0.1:8712/` 真实截图 |
| 数据库文件 `qoder/data/*.db` | 本机生成，已被 `.gitignore` 排除，不入库 |

演示数据里出现的「课程」「学员」均为泛化称呼，不含真实姓名、账号、手机号或邮箱。
