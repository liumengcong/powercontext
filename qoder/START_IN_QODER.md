# 给 Qoder 的完整开发任务

请主要由 Qoder 在当前仓库实现以下项目，执行、调试并保留真实开发记录。所有项目文件放在 `qoder/` 下。当前文件属于开发需求，不能当作已实现功能。

## 项目定位

中文名：研习台。英文名：StudyFlow。
一句话：让下一次学习，从上次的进展继续。

场景：学生和科研人员的笔记、薄弱点、待办常分散在多个会话中。项目保存用户明确确认的信息，在重新打开应用时召回，生成有出处的继续学习清单与复盘初稿。

## 强制条件

1. 必须真实使用 PowerContext 开源组件承担核心记忆持久化与跨会话召回。不能用 localStorage、自写 SQLite 表或假接口替代后声称接入成功。
2. 可采用 PowerContext 的 builtin runtime，在应用进程内通过官方 Python API 使用 SQLite 持久化。此方案满足选择 PowerContext 的技术路线；不声称独立接入 seekdb。
3. 调研并锁定实际可安装的稳定版本。准备阶段发现 PyPI 可安装 `powercontext[builtin]==1.5.1`；主分支文档已写 1.5.2，但该版本当时尚不能从 PyPI 安装。请检查安装包的实际接口，避免照抄新版文档。
4. 用 Qoder 完成主要开发、调试，保存对话截图或录屏、开发时间、主要变更和可核对的会话记录。
5. 最终用 Qoder Sites 发布项目展示网站，并设置任何人可访问。网站可展示截图、运行方式、代码链接；如果 Sites 只承载静态页面，必须把互动演示与真实后端的边界写清楚，不能把静态演示当作已接通的后端。
6. 不虚构 UID、网站地址、真实用户反馈、使用人数或提效百分比。
7. 不提交真实密钥、用户数据库、登录会话文件。

## 建议实现

后端：Python 3.11 或 3.12，FastAPI、Uvicorn、PowerContext builtin runtime。前端采用轻量 HTML/CSS/JavaScript 或 React；选择易复现、维护简单的方式。默认绑定 127.0.0.1，初版是本地单用户工具，不宣称支持公开多用户。

### 页面与主要流程

- 总览：本次要继续的任务、最近学习记录、仍待解决的薄弱点。空状态指引导入演示数据。
- 记忆库：创建笔记、偏好、薄弱点、进度与待办；类别清晰；提供原始文本、创建时间、PowerContext artifact ID/revision 与详情。
- 继续学习：重新启动后读回上次进度与偏好，生成“已完成 / 当前阻塞 / 下一步 / 参考记忆”。偏好真实影响建议，比如可用时长为 25 分钟时，给出相应的任务数量和明确的规则说明。
- 检索：调用 PowerContext 的真实查询能力，检索结果展示原文和精确引用；中文检索行为必须实测。若官方文本分词对中文有限制，明确解释并使用可验证方案，不能伪造语义检索。
- 待办：创建、完成、恢复，状态更新持久化；处理预期版本冲突，避免覆盖并发修改。
- 复盘导出：根据实际记忆与待办生成 Markdown 初稿，包含引用和“需本人核对”提示；不补写没有记录的成果。下载使用 UTF-8。
- 验证记录：记录应用对 PowerContext 的真实写入、读回、查询与版本更新的操作结果；不记录密码与令牌。
- 演示数据：从 sample-data.json 导入，重复点击不重复创建；使用独立演示 scope，不混入用户数据。

### 视觉

桌面端左侧导航、右侧宽内容区；浅色暖灰背景、深蓝文字、青绿色强调色；中文可读字体、充足留白。顶部写“今天，从上次的进展继续”；右上角显示真实服务连接状态。记忆卡片使用类别色标、正文摘要和“查看出处”。对断开、加载、输入错误、空结果提供明确反馈。移动端可正常操作。

### 数据设计原则

- 使用 PowerContext scope 隔离不同工作区；scope 是数据选取边界，不能当作用户认证。
- 事实来源为 PowerContext artifact。允许应用存放非核心 UI 配置和导入去重映射；主记忆不能仅存于浏览器。
- 新会话推荐必须重新从 PowerContext 读取，不能仅使用当前页面内存。
- 需要 JSON 包装文本时保持模式版本并解释，避免损害全文检索；优先使用 kind、description 和 text 的真实能力。
- 显式保存无需模型 API；规则整理注明规则，不将其包装成生成式 AI 或语义推理。

## 必须交付的文件

1. 可运行完整源码、锁定依赖、`.env.example`、`.gitignore`。
2. README：从干净环境安装到启动的全部步骤、端口、数据位置、功能边界、故障排查。
3. 至少一组端到端验证：保存 -> 进程重启 -> 读回 -> 偏好影响下一步 -> 完成待办 -> 再次重启验证 -> 导出带引用复盘。
4.  meaningful tests：记忆持久化、工作区隔离、查询真实命中、状态更新及冲突、空结果不编造、输入安全。至少一个测试用真实 PowerContext，不能全是 mock。
5. `docs/开发记录.md`，保留真实会话/录屏的索引；缺少的人类材料显式标为待补。
6. `docs/验证结果.md`，只写真实运行结果和命令；失败也要记录。
7. `site/` 项目展示站点：简介、痛点、核心功能、真实截图、源码链接、运行说明和体验入口；待填地址要清楚提示。
8. 可复制项目说明与演示讲稿，根据最终实际实现编写。

## 工作步骤

先核对当前依赖 API、列出短计划；实现真实 PowerContext 读写最小链路；完成前后端主要流程；按 `docs/验收样例.md` 执行；修复后整理运行说明、截图与开发记录。最后准备 Sites 展示站点，并在发布前核对个人账号与公开可见性。

开发期间保留真实证据；不要把当前需求稿计入 Qoder 已完成的功能。不需要编造真实用户效果；可以提供一份空白试用记录表供后续填写。
