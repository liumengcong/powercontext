## 1. 生成最后一项必需证据

按 `MiniMax开通说明.md` 取得 Key 和可用额度，在 `minimax/` 执行：

```bash

```

如果尚未安装环境，macOS/Linux 可先执行 `bash 一键完成.command`，脚本要求本机已安装 Python 3.12。它会安装锁定依赖，然后运行同一个完成流程。

完成后检查：

- `reports/evidence/minimax-request.json` 与 `minimax-response.json` 真实存在。
- `reports/evidence/summary.json` 中六个 checks 均为 true，mode 为 live。

- `reports/submission-status.json` 的 `materials_complete` 为 true。

## 2. 把最终材料提交到 minimax 分支

如果直接在提供的本地工作仓库操作，在该仓库根目录执行：

```bash
git switch minimax
git add minimax
git commit -m "feat(minimax): record actual MiniMax code generation and validation"
git fetch participant minimax
git merge --allow-unrelated-histories FETCH_HEAD --no-edit
git push participant minimax
git rev-parse HEAD
```

已核对你的远程 `minimax` 分支当前从主线代码创建，尚无本作品目录。上面的 merge 会保留该分支现有历史，同时纳入官方生态比赛基线；出现冲突时先合并处理，不要强制推送。最后一条输出的 **40 位完整 Commit ID** 才是最终填写内容。不要使用尚缺真实模型记录的交付初始提交 ID。推送需要你本机已登录 GitHub 或通过 Git 凭据管理器认证；本交付不包含登录凭据。

如果在自己的已有仓库操作：先切换到 `minimax`，检查并合并交付包中的 `powercontext/minimax/` 到仓库同名目录，不覆盖已有修改；完成真实验证、commit 后推送 `origin minimax`。也可使用交付的补丁，先执行 `git apply --check 补丁路径`，只有检查通过再执行 `git apply 补丁路径`；失败则需先合并冲突。如果该分支尚不存在，可从官方比赛分支新建：

```bash
git switch 2026-competition-ecosystem
git switch -c minimax
```

若 `minimax` 已存在，请先保留并检查已有修改，不要使用强制推送覆盖。若本地没有官方分支，从 upstream 官方仓库取得该分支后再创建；不要从其他题目分支随意开始。

推送后打开 `https://github.com/liumengcong/powercontext/tree/minimax`，确认能看到 `minimax/README.md`、`minimax/reports/evidence/` 和与本地一致的最终 Commit ID。
