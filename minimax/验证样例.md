# 验证样例：订单金额下限筛选

## 任务与兼容要求

修改 `business/orders.py::list_orders`，实现 `min_total`，金额单位为整数分。`None` 表示不筛选；非负整数包含边界匹配；拒绝 bool、负数、浮点数、NaN、Inf 和字符串。保留 status 的原有合法值/异常、输入顺序、不修改输入和返回项浅拷贝。有效规格为 `specs/orders.json` 的 `ORD-001` 至 `ORD-004`；`ORD-000` 已退休，不得作为当前要求提供。

初始订单在 `tests/conftest.py::orders`，依次为 A/paid/0、B/pending/999、C/paid/1000、D/cancelled/2500、E/paid/5000。筛选 1000 应得到 C、D、E；与 paid 组合应为 C、E；0 保留全部；6000 返回空。非法 min_total 必须抛出名称包含 min_total 的 ValueError。

## 必须包含的来源

`demo/task.json` 的 `required_source_ids` 是自动检查清单，至少包括：

- `ORD-001`、`ORD-002`、`ORD-003`、`ORD-004`。
- `business/orders.py::list_orders`。
- `tests/test_feature.py::test_min_total_boundary`、`test_min_total_combines_status`、`test_min_total_rejects_invalid`。
- `tests/test_regression.py::test_orders_status_filter`、`test_orders_independent_copies`。

真实返回还包含零下限、超上限、不修改输入和其他回归测试及初始订单 fixture。来源 ID 中的 `::` 分隔真实文件与符号。代码/测试行号由 AST 计算；规格文件路径加条目 ID 定位规格。

## 重置

重新执行 verify 命令会自动创建空数据库、空任务状态和旧业务实现的新副本，因此不需要删除任何旧记录。手工演示时在新的项目副本覆盖 `fixtures/before/orders.py`，并传入新的 `--runtime` 即可。已有参考记录/最终证据留作审计，不直接覆盖。
