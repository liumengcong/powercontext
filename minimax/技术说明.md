# 一页技术说明：规有所依

本作品为使用 MiniMax 的开发助手提供 SDD 工程上下文。局部任务为订单读取接口增加非负整数分的金额下限，同时保留状态筛选、稳定顺序、输入不变和返回项浅拷贝等兼容行为。交付的参考实现已通过测试；真实 MiniMax 开发记录由使用者配置 Key 后生成。

| 层 | 实现与职责 |
| --- | --- |
| 工程采集 | JSON 规格只采集 active 条目；AST 提取 Python 顶层代码/测试符号。保留来源路径、行号、版本和文件 SHA-256。所有输入先解析和校验，再在事务中替换项目索引。 |
| seekdb 检索 | `sdd_documents` 保存规格正文、代码和测试。将任务拆为关键词，执行带绑定参数的 SQL 查询；查询返回的真实记录是开发上下文的来源。默认通过 pylibseekdb 启动真实本地 seekdb，也可接 OceanBase MySQL 模式。 |
| 上下文构造 | 对查询结果按任务词相关性排序，分规格/代码/测试组合；所选来源逐个校验实际文件哈希。缺失某类来源、过期文件或预算不足都明确报错。输出 SQL、参数、返回来源身份以便审计。 |
| PowerContext 状态 | 使用官方内置 Artifact 持久化接口保存 `sdd-task` 的任务、已完成、待办、测试结果和代码/规格/测试综合指纹。新进程重新打开数据库，读取最新 Artifact 修订版，并把状态实际加入下一次模型上下文。 |
| MiniMax 开发助手 | 通过官方 OpenAI 兼容 HTTP 接口接收上述上下文，返回唯一允许修改的业务文件。保存非私有推理的请求/响应记录和代码哈希。默认模型为核对时的 `MiniMax-M3.1-Flash`，实际返回模型以响应记录为准。 |
| 可复核验证 | 相同目标功能测试修改前因断言失败/未抛预期异常而失败，修改后通过；原有回归测试前后均通过。测试文件哈希不变。每条记录包含命令、退出码和代码/测试/规格内容指纹。 |

规格更新采用“修改文件 → 重新导入 → 查询最新记录”的规则，不返回预制答案。撤回的条目不再进入索引；文件变动后未导入会阻止使用旧来源。已保存测试结果的指纹与当前项目不同时，记录仍保留，但标记验证过期并要求重测。规格变更探针把包含边界改为严格边界，验证检索确实返回新内容；该探针随后恢复，最终业务实现仍按 v1 包含边界规格验收。

完整链路：导入 → seekdb 查询 → 上下文 → PowerContext 保存 → 进程退出 → 新进程读取 → MiniMax 修改 → 同测试验证 → PowerContext 保存完成状态 → 再次新进程复用。模块没有硬编码返回固定上下文；对无关查询会明确指出没有相关来源。

实现取舍：小型单项目完整替换索引、SQL 关键词匹配和字符预算使验证透明且无需 embedding 密钥；没有向量检索性能、成本节省或大规模适用性的未经实测宣称。PowerContext 使用独立 SQLite 持久化，seekdb 实际负责工程资料存储和检索，两者职责分别有可执行记录。
