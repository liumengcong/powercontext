# 从打开文件到提交比赛

你有 Dify Cloud 账号，按下面顺序操作。**最终提交物是 GitHub 私有仓库里的项目和对应分支/提交号，不是一段“标准答案”。**

本次已做完源码、DSL 和真实 PowerContext 后端验证；还需要你在账号内导入、运行，随后推送仓库和提测。

## 一、先把后端启动起来

1. 解压项目包，打开 `dify` 文件夹。
2. Mac 双击 `一键启动_Mac.command`。它会安装项目依赖、生成仅本机保存的 `.env`，然后启动后端。需要 Python 3.11—3.13，建议 3.12。没有可用 Python 时，按窗口提示从 Python 官网安装 3.12 后重试。
3. 看到 `Uvicorn running on http://127.0.0.1:8787` 后，保留终端窗口。
4. 浏览器打开 `http://127.0.0.1:8787/healthz`，应出现 `status: ready` 和 `powercontext: 1.2.0`。
5. Finder 如果隐藏点文件，按 `Command + Shift + .`。用文本编辑器打开 `.env`，找到 `BACKEND_TOKEN=` 后的一长串值，稍后填进 Dify。**不要把整个 .env 上传 GitHub，也不用发给聊天助手。**

双击文件被系统拦住时，可在终端进入该目录执行 `zsh 一键启动_Mac.command`。原生终端步骤和 Docker 步骤都在 `docs/运行说明.md`。

## 二、给 Cloud 一个能访问的后端地址

**Dify Cloud 不能访问你电脑的 127.0.0.1 / localhost。** 这一步不能省。

自己试玩的最短路径：双击 `临时公网联调_Mac.command`。它使用 Cloudflare 官方 cloudflared，为本机后端创建临时 HTTPS 地址。复制终端里形如 `https://某个随机名字.trycloudflare.com` 的整段地址。后端窗口、隧道窗口都要保持开启，电脑不能休眠。

临时地址会失效，**不适合作为评审期唯一入口**。正式提交时，建议把后端按 `docs/运行说明.md` 的长期服务方案部署到你可用的服务器，配置长期 HTTPS 地址，并保留数据目录。评审也可以按交付的源码、Docker 配置在自己的环境重建后端，再改两个 Dify 环境变量。题目允许这种可复现方式，不强制单独开发前端。

本项目没有替你购买服务器或创建云资源。如果你只有 Cloud 账号而没有长期服务器，可以先用临时地址完成自己的 Dify 实测；交付时一定保留完整源码和部署说明，不要声称临时链接永久可用。

## 三、先导入无模型自检版

1. 登录你的 Dify Cloud，进入工作室。
2. 找到“创建应用 / 导入 DSL 文件”入口；不同语言版本名称可能略有差别。
3. 选择 `dsl/00_无模型连通性自检.yml`。
4. 打开工作流里的环境变量面板，配置：

| 变量 | 填什么 |
| --- | --- |
| BACKEND_BASE_URL | 第二步得到的公网 HTTPS 地址，末尾不带 `/` |
| BACKEND_TOKEN | 本机 `.env` 中同名字段的值，类型保留为 Secret |

5. 点击测试运行，填入：

```text
player_key：trial-2026-001
action：寄存
message：会打嗝的月亮
```

6. 应看到“无模型自检旁白”、物品档案、三组选项和记忆版本 `0 → 1`。这个工作流不调用聊天模型，用于验证 Cloud 到后端与 PowerContext 的真实连接；**它不是正式 AI 作品的替代品**。
7. 再运行一次，使用同一 `player_key`，`action` 选“回访”，`message` 留空。应恢复同一物品，版本不增加。

如果失败：

- 401：核对两处 `BACKEND_TOKEN` 完全相同，没有误粘贴 `BACKEND_TOKEN=` 字样。
- 连接失败 / 502 / 超时：先在浏览器打开公网地址加 `/healthz`；检查两个终端窗口是否还开着。
- 422：按返回提示改输入；已有存档不能重复“寄存”，需先“重开”或换一个新存档口令。
- 导入提示模型或版本问题：确认导入的是 `00_` 文件，保留错误信息；不要把文件扩展名改成其他格式。

## 四、导入正式 AI 版

1. 再创建一个新应用，导入 `dsl/01_离谱失物招领处_AI正式版.yml`。
2. 同样配置 `BACKEND_BASE_URL` 与 Secret `BACKEND_TOKEN`。两个应用的环境变量互不自动复制。
3. 点击“AI 柜员讲述本回合”节点，**重新选择你账号里已经授权、额度可用的聊天模型**。文件预填 DeepSeek `deepseek-chat`，你可以选其他支持中文的聊天模型。若使用预填模型，在 Cloud 模型供应商设置中启用官方 DeepSeek 插件并配置自己的模型 API Key。Dify 登录账号和模型服务额度是两件事。
4. 保存节点，测试运行。使用一个全新存档口令，例如 `final-2026-001`，避免与自检版的存档冲突。
5. 按 `docs/验证样例.md` 的顺序运行：寄存 → A → 回访 → B → C → 新玩家档案。
6. 展开 Dify 执行追踪，保留读取记忆、LLM、提交记忆三类节点成功的记录（日志、截图或录屏均可）。至少保留一次新运行中“回访”找回旧物品和先前选择的证据。
7. 点击发布，复制发布后的体验链接。你选择的模型及其费用由自己的模型账户承担。

如果 AI 柜员节点失败，后面的提交节点不会执行；本回合不推进。修好模型后重新运行即可。模型调用可能产生费用，先用少量样例测试。

## 五、生成真实 Cloud 验收记录

正式版发布后，在应用的“访问 API / API 密钥”区域创建该应用的 API Key。此 Key 填入本机 `.env` 的 `DIFY_API_KEY`；不用上传、不用发给聊天助手。

本机 `.env` 还要把 `BACKEND_BASE_URL` 改成当前可访问的后端地址。然后双击 `运行Cloud实测_Mac.command`。脚本只调用你自己的已发布应用，进行六次真实 Dify 运行，保存：

```text
evidence/dify_live_acceptance.json
```

只有该文件的 `status` 为 `passed`，并且你检查了 AI 旁白确实合理地回应了历史细节，才能说正式链路已通过当前环境验证。脚本不会用 mock 或规则旁白冒充模型调用。

把这份实际记录、可选截图、实际 Cloud 界面版本信息、模型名称及官方供应商插件版本补充进 `evidence/`。对外分享截图前遮住口令和 Key。`.gitignore` 默认忽略这份新生成的 Cloud 记录；检查确认没有凭据后，可以通过 GitHub 网页上传该 JSON，或执行 `git add -f dify/evidence/dify_live_acceptance.json`。

## 六、放进比赛私有仓库

官方要求基于 `oceanbase/powercontext` 的 `2026-competition-ecosystem` 分支，将材料放进 `dify/`。

最容易的网页方式：

1. 登录 GitHub，打开 Import repository 页面。
2. 导入来源填 `https://github.com/oceanbase/powercontext`，给自己的仓库起名，**Visibility 选 Private**。如果你之前已按比赛要求导入过，直接使用原私有仓库，不必新建。
3. 导入完成，打开仓库，左上角分支下拉框切换到 `2026-competition-ecosystem`。不要上传到 `master` 或 `2026-competition`。
4. 点 Add file → Upload files。网页上传请先将不含环境和凭据的交付 ZIP **重新解压到一个干净的新目录**，再把其中的 **dify 文件夹**拖进去，并补上自己的实际 Cloud 记录（截图可选）。不要直接拖入已经安装运行过、含 `.env` / `.venv` / `.tools` / `data` 的本机工作目录。上传后路径应为 `dify/README.md`、`dify/dsl/...`、`dify/backend/...`；不要变成 `dify/dify/` 或多包一层外部目录。
5. 确认没有 `.env`、`.venv`、`data` 或真实 Key。把你新生成且检查过的 Cloud 证据一起上传。
6. 提交说明可以写 `Add Dify lost-and-found game with PowerContext memory`，选择提交到当前比赛分支。
7. 打开最新一次提交详情，复制 **完整 40 位 SHA**。这是提交代码的版本号，每次重新上传代码后都会变化。

如果项目文件多导致网页不方便上传，完整 Git 命令见 `docs/运行说明.md`。新增源码包约百 KB，不包含模型、依赖环境或数据库。

## 七、回到比赛平台提测

1. 在“参赛信息”中核对 PowerContext 生态题所用的比赛私有仓库地址，并按官方 GitHub 指引配置让判题端能够读取私有仓库的授权。优先使用只读且仅授权该比赛仓库的凭据。
2. 若平台要求带访问凭据的仓库 URL，**只在比赛平台指定字段填写**；不要把这个地址写进项目、截图、README 或聊天。
3. 打开你发给我的这道 Dify 题，进入提交/提测区域。
4. 按字段名填：

```text
分支 / branch：2026-competition-ecosystem
提交号 / commitId / Commit SHA：你刚才复制的 40 位最新提交 SHA
```

5. 如果页面提供说明字段，可粘贴 `提交说明_可复制.txt`。没有说明字段就不用额外找地方粘贴，项目 README 已包含说明。
6. 确认分支和 SHA 没填反，点击提交。之后查看评测状态和失败日志。仓库已推送、判题端能读、SHA 能检出是基础条件。

不要把这个源码包的基础 SHA 当成你的最终 SHA；不要向官方仓库提 PR 来代替本题提测。

若失败，把 **去掉凭据后的错误日志**留给后续排查。对于当前交付，Cloud 导入和真实模型调用还需要你完成，尚无可保证的官方分数。
